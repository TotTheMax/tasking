## Context

`segment-turn-cards`（ADR 0041）把轮次卡片改成「一个有序事件流 + 溢出优先分段」：每个面板保留完整 15 行输出，超 24KB 就把最新尾部放到新卡。结果是长轮次单卡只有 10–20 个工具，用户要翻几张卡才能看清「agent 做了什么」。

飞书的约束没有变：单卡请求体 ≤30KB、≤200 元素/组件、≤5 表格；**折叠面板的内容即使默认收起也计入卡片 JSON 体积**。所以「隐藏但保留」不省空间——输出要么在卡片里占字节，要么不在卡片里。

旧实现（`8a3a1bb^`）的降级阶梯是：最旧优先，15 行 → 3 行 → 去掉输出（保留 Args/Command）→ 丢弃整个面板并在末尾显示「还有 N 个未展示」。它让一张卡能装 40–50 个工具，但会丢面板，且极端情况下整卡没有任何 Output。

本 change 结合两者：**降级到「只有输入」优先；仍装不下才切段；永不丢面板；最新尾部保持完整。**

## Goals / Non-Goals

**Goals:**

- 单卡重新装下 30–50 个工具（密集历史卡），最新几步保留完整输出。
- 永不丢面板；「还有 N 个未展示」彻底消失。
- 溢出时优先降级旧面板输出，而不是立刻切段；只有降级到极限仍装不下才切段。
- 多段轮次明确显示 `本段 X · 本轮 Y`。
- 不新增配置、数据库列或 feature flag。

**Non-Goals:**

- 单卡窗口模式（`window`）或任何 `card_overflow` 配置。
- 面板级「按需查看输出」按钮（未来可选项）。
- assistant 文本降级（保持完整；单条超预算才截断）。
- 表格数（≤5/卡）处理、卡片内容脱敏、`reasoning` 上卡。
- 改变结果卡、`📄 完整输出`、1MB 明细上限、按钮/守卫/持久化语义。

## Decisions

### 1. 实时降级（不是切段时才压缩）

当前卡超预算就先把最旧面板的输出降级，新事件继续以完整明细加入同一张卡。这样当前卡能持续填充到密集容量（约 56 个工具或 24KB），而不是像「切段时才压缩」那样每张卡仍停留在 10–20 个。

被否决：切段时才压缩（密度不提升，只是把输出消失推迟到封存瞬间）。

### 2. 全局分轮降级（沿用旧逻辑）

降级顺序保持旧代码的语义：

```
target = 1: 最旧面板 15→3，逐个向前，直到所有面板都 3 行
target = 2: 最旧面板 3→无输出，逐个向前，直到所有面板都无输出
```

不使用「逐面板降到底」：全局分轮能让每个工具都保留一点结果（3 行），且与旧卡观感一致；实现上也是对现有循环的最小修改。

### 3. 输入截断 + 永不丢面板

level 2 下单个面板的 `Command`/`Args` 保留约 2KB；如果整卡仍超，继续截断到刚好放下（保留 `…` 标记）。单面板最终只剩「工具名 + 状态 + 截断后的输入」，一定装得下。

因此 **level 3（丢弃面板）和「还有 N 个未展示」标记被移除**。如果出现渲染 bug 导致仍超限，走既有 Card fallback（整轮合并文本），而不是悄悄丢面板。

### 4. 文本保持完整

assistant 文本是「为什么这么做」的主要载体，且通常远小于工具输出。文本不参与降级；只有单条文本自身超过整卡预算时，才截断到预算内（现有 `truncateSingleTextToFit`）。

### 5. 装箱：先整组降级，仍装不下才切段

每次 flush 按下述顺序：

1. 整组事件按 level 0 试；装得下 → 一张卡，结束。
2. 否则先尝试**整组**按全局分轮降到 ≤2；装得下 → 一张卡（旧面板只有输入，最新面板保留尽可能高的细节），结束。**真机反馈后修正的关键**：不要为了保住「最新 25 个面板完整」而把只有 8 个工具的旧前缀切出去，那会产生 8/3/2 这样的短历史卡。
3. 整组降到无输出仍装不下 → 切段：找到最大的完整尾部 S（从尾部向前能按 level 0 装下的最大后缀），P = 其余事件；P 按密集容量（level ≤2）**均衡**装箱成一张或多张历史卡（避免 1–3 个工具的短卡），S 作为最后一张完整明细卡（活跃）。
4. 单条事件自身完整装不下时，先就地降级（工具去输出 + 输入截断；文本截断）；后续事件 MAY 继续留在同一张卡，只有降级后仍装不下时才让它独占一个分段。

S 的边界、P 的均衡装箱都用「字节 + 元素估算」判断，与现有 `cardFits` 一致；不设段数上限。

被否决：为保最新完整而优先切段（真机实测会产生 8/3/2 个工具的短历史卡，密度反而更差）；只切一刀（前缀可能仍超）。

### 6. 「最新完整」是尽量，不是保证

降级从最旧面板开始，最新面板保留预算允许的最高级别；只有整组降到无输出仍装不下时才切段，此时最后一张卡（完整尾部）保持 15 行输出。**不承诺**「最新面板始终完整」——真机反馈表明，为了这个承诺切出多张短历史卡，整体体验更差。密度优先。

### 7. 计数文案

正文第一行在多段轮次显示 `🔧 本段 X · 本轮 Y`（英文 `X this card · Y turn`）；单卡轮次保持 `🔧 N`。`X` 是该卡实际渲染的工具数，`Y` 是该卡最后一次渲染时的整轮工具数（历史卡为封存时的快照）。是否显示由轮次级标记 `segmented` 决定，而不是靠 `X !== Y` 判断——否则「最后一张恰好包含全部工具」会错误地退化成单卡文案。头部继续用 `片段 N` 定位，不额外加长。

### 8. 不变的部分

旧段 footer（「本段结束，续见下一条卡片」）、轮末 footer、只有活跃段带按钮、`stop/retry/full` 活跃段守卫、`📄 完整输出`（整轮工具明细、1MB）、`finalized` 去掉最后一段文本、`direct_sessions.card_message_id` 只存最新段——全部保持。

### 9. 决策记录

新增 **ADR 0042 `degrade-before-split`**，说明「降级优先、分段兜底、永不丢面板」以及与 ADR 0041「优先分段」的关系；ADR 0041 顶部加 `amended by ADR 0042` 指针（不改原文）。

## Test Seams

按 TDD 约定，测试只落在以下公共边界：

1. **`buildTurnCard(state)`**：纯渲染函数。断言面板的 level 结果（完整/3 行/无 Output）、输入截断、无「未展示」标记、`本段/本轮` 文案；不测内部循环。
2. **`DirectSessionManager` + 注入的 Feishu mock**：通过 `replyCardInThread` / `updateCard` 观察「哪些事件落在哪张卡、卡片内容是什么」，验证实时降级、单卡降级优先、密集历史卡装箱、最新完整尾部、永不丢面板；不断言私有方法或调用次数。
3. **真实飞书 smoke**（`tests/integration-turn-card.test.ts`）：只验证 API 接受（交错卡、近预算更新、续段卡、50 面板密集卡），不验证视觉。
4. 视觉/手感由 final-only 人工冒烟确认，不作为阻塞门禁。

## Risks / Trade-offs

- **[用户正在看的旧面板输出会消失]** → 这是实时降级的固有行为，与旧卡一致；最新面板保持完整，历史输出可从 `📄`/TUI 获取。
- **[极端密集卡可能触发元素上限]** → 保留 180 元素估算；约 56 工具/卡为上限，超出继续切段。
- **[输入截断到 2KB 可能丢失关键参数]** → 只对历史面板生效；最新完整卡不截断；编辑类工具的大段内容本来也不适合在卡片里阅读。
- **[渲染/测量次数增加]** → 每次 flush 需要试整组、找尾部、试一张卡、密集装箱；用二分/贪心，事件数在同一 flush 内通常 10–50，成本可控。
- **[最新尾部可能只有一条事件]** → 这是保护最新内容的下限；该事件会按单条兜底渲染。
- **[单卡 >5 表格仍会整卡失败]** → 既有已知限制，未在本 change 处理；失败走 Card fallback，下一轮自愈。

## Migration Plan

1. 无配置/数据库迁移；部署后长轮次的展示自动变为密集历史卡 + 完整最新卡。
2. 回滚：revert 代码；运行中可用 `feishu.direct.verbosity: summary` 立即退回文本交付。
3. 归档顺序：本 change 的 spec delta 基于 `segment-turn-cards`（ADR 0041）已生效后的行为；**必须先归档/同步 `segment-turn-cards`，再归档本 change**，否则主 spec 的轮次卡片需求会缺少分段语义。
