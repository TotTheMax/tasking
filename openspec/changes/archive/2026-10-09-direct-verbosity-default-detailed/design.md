# Design — verbosity 默认 detailed

## 决策

只翻默认值，不动 verbosity 三档语义、不动卡片机制（ADR 0024 的卡片形态、预算、降级路径全部保留）。显式 `summary` 是完整的回退路径，老客户端用户可一行配置回到纯文本。

## 取舍

- **否决「服务端探测客户端版本、按人降级」**：飞书卡片 API 不暴露查看者客户端版本；卡片 JSON 是一次性分发的，无法按接收者定制。
- **否决「默认 detailed + 检测到占位符反馈时提示改 summary」**：没有信号回路（占位符是客户端本地渲染，不产生回执）。
- **否决「新增第四档 auto」**：auto 与 detailed 无差异（无法探测就没有 auto 的依据），多一档配置面 + 双语文档 + 校验，纯成本。
- **接受的风险**：默认部署下老客户端（< V7.9）用户看到「请升级」占位符。缓解：①版本要求写入模板注释与双语文档；②占位符本身是飞书官方升级提示，非报错；③结果卡片超预算降 `.md` 附件、卡片 API 失败降文本等既有兜底不受影响；④一行 `verbosity: summary` 显式回退。

## 连带影响评估

- **API 配额**：默认路径从「每 turn 1 条文本」变为「每 turn 1 卡创建 + 周期 PATCH（1.5s 合并）+ 1 结果卡」，调用量上升；ADR 0024 的合并/预算硬上限保留，且卡更新不产生推送。接受。
- **一次性控制台配置**：`im:resource` + `card.action.trigger` 订阅成为默认前置；未配置时按 ADR 0024 降级为合并文本消息（WARN），不阻断。文档写明。
- **既有部署**：显式写了 `verbosity: summary` 的不受影响；没写 verbosity 的升级后行为变化——这正是变更目的，release note 提及。
