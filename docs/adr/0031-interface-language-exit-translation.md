# Interface language via exit translation + coverage-tested dictionary

tasking needed bilingual (zh/en) interface text — Feishu replies/toasts/cards, CLI output, TUI — under two hard constraints: existing Chinese source strings stay untouched, and existing zh tests stay green. We rejected a full i18n catalog (~400 call sites rewritten to keys plus test churn) and inline `L(locale, zh, en)` wrapping (~400 one-line diffs plus locale threading through pure render functions). Instead, `translate()` runs at the outbound exits (Feishu send/reply, toast, card JSON walk skipping protocol fields, CLI stdout, TUI cell text before width math) against a two-layer dictionary: exact-match for static strings, ordered regex frames with `$1` passthrough for interpolated ones (variables are keys/paths/English errors, which should never be translated anyway). Because exit translation alone would let future Chinese strings silently leak to English users, `tests/translate-coverage.test.ts` scans every Han string/template literal in `src/` (with a template-aware scanner, unescaped to runtime semantics) and fails CI unless each is covered by the dictionary or an explicit whitelist (initially only the legacy `via 飞书` sentinel matcher). The bridging sentinel itself became locale-independent `via Feishu` with dual-prefix reading so old comments still dedupe. Accepted trade-offs: no third language without a mechanism rewrite (zh/en only by decision), and ternary-embedded Chinese inside passed-through variables stays Chinese in en mode (flagged by the runtime residual-Han warn).
