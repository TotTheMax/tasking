# Auto-continue：直连会话的行为驱动续跑，而不是任务内完成协议

直连 `/chat` 会话目前一条用户消息只跑一轮；模型在长任务中提前总结收尾时，用户只能每轮手动回“继续”。Jira 路径已有 `agent.max_turns` 有界续轮，直连没有。直觉方案是往任务 prompt 里加“完成时输出 `DONE`”，但这会把模型推向收尾态，正好强化要解决的问题，并污染上下文。

本 ADR 记录选择：**Auto-continue 是直连会话的显式模式（`/loop on [N]` 只 arm，`/loop start [N]` 立即继续），按“有没有新动作 / 是否重复 / 是否在提问”决定软暂停或硬停；完成判定不进入任务会话，也没有 `/accept` 或 LLM 裁判。** 预算只计自动轮（默认 5，1–20），用户轮不消耗；`agent.max_turns` 保持 Jira worker 专属。`turn_timeout` / `inactivity_timeout` 作为普通自动轮重试，只受预算封顶；`permission_timeout`、`failed`、用户/daemon 中断硬停。UI 上只给过程卡 header 加 `🔄 自动 n/N`，结果消息保持纯回答，暂停/停止另发一条文本；不做结论卡、停止章或卡片按钮。

被否决的方案：**任务内 `DONE` 协议**（行为偏移、上下文污染、需要从正文剥离标记）；**外部 LLM 复核**（每轮多一次调用，且并不比自报可靠；留作 v2 插槽）；**`/accept` 验收命令**（确定性最强，但把任务编排塞进自动化流程，v2 再做）；**无条件续跑**（成本无界）；**复用 `agent.max_turns`**（会把 Jira worker 与直连预算绑死，默认 20 也太贵）；**Jira 路径也自动续跑**（Jira 已有自己的有界续轮）；**结论卡/停止章/按钮**（分段卡片下停止章要处理“只盖最后一段”和 24KB 预算，收益不抵复杂度）。

**Consequences.** 最坏情况下预算允许 5 次、每次 1 小时的超时重试；这是用户明确选择的“只靠预算封顶”，日志记录 `duration_ms` 与 `auto_continue_turn` 指标，可随时 `/stop`。误暂停的成本是一句话（软暂停），误继续的成本由预算兜底；跑一周后再决定是否调常量或引入 v2 外部复核。`direct_sessions.loop_prompt` 持久化会话提示词覆盖，循环状态本身不跨重启。Jira 绑定话题的 `/loop` 必须回提示且不桥成评论（话题二分不变式）。需求与测试见 OpenSpec `auto-continue`。
