# 飞书入站改事件驱动（WS 长连接），轮询降级为兜底清扫

取代 ADR 0003。飞书入站改用官方 SDK（`@larksuiteoapi/node-sdk` 的 `WSClient`，仅此一处 import）订阅 `im.message.receive_v1`：事件归一化成 `FeishuPolledMessage` 后实时进入站队列（与 Sweep 共用单一入队口，msg_id 先到先得 claim，单消费者串行）；REST 只保留发送、冷启动探测和 Sweep。触发动因是**配额**而非延迟：免费版额度是租户级共享（基础免费版限时 100 万次/月，2026-03 起），2s 轮询 × (1+活跃 binding 数) 单实例一天烧 ~13 万次，多用户同租户必然互相挤兑；事件推送不计额度（豁免通道），收侧成本归零。Spike 已实证：配额耗尽状态下 WS 照常建连收消息，话题回复事件携带 `root_id`/`parent_id`/`thread_id`（`omt_*` 格式与 bindings 一致），可直查 binding 路由。

为什么推翻 0003：其前提是"零新依赖、全轮询极简、延迟不重要"，现约束反转为"额度硬稀缺、实时性顺带白拿"；0003 自己预留的出口（"大规模才咬限流——届时再上长连接"）即本次。0003 担心的持久连接复杂度（心跳/重连/3s ack 约束）被隔离在 ~100 行 `FeishuEventListener` 薄适配层（含 SDK→内部消息形状归一化），桥本体 SDK-free、测试形状不变。事件处理失败不回传平台（入队即 ack），瞬时失败由进程内 3 次退避重试兜住（重试打 Jira，零飞书额度成本），终态失败维持现状语义：可见失败 ack + 游标推进。

配套：轮询代码不删除而降级为 **Sweep**（启动时 + WS 重连成功 + 12h 安全定时器三个触发），只补停机/断线窗口与静默异常；配置键拆为 `feishu.forward_interval_ms`（原 `poll_interval_ms` 改名，Jira→飞书镜像快循环，默认 5s，镜像延迟不再随收侧变化）与 `feishu.sweep_interval_ms`（新增，默认 12h），旧键硬删不做别名。WS 不可用自动退化（WARN + 60s 重试，功能不残缺只是延迟回到 sweep 节奏），无 `receive_mode` 开关；429 冷却（60s 起翻倍封顶 10 分钟，成功复位）保护残余 REST 调用。约束：**单实例假设——已由实例锁强制**（2026-09-01 起，同一 app_id+intake_chat_id 在 `~/.tasking/instances/` 加 pid 锁，第二个实例启动即失败；此前仅靠文档约束，实际发生过双实例各自 dispatch 给同一任务建重复话题的事故）；长连接需一次性控制台配置（订阅方式=长连接、添加事件、发布版本），未配置时按降级稳态运行；真实事件流无法全自动测试（事件须由 `sender_type=user` 消息触发），以半自动脚本（人工发一条消息、断言全自动）+ 建连冒烟替代。

被否：① 保持纯轮询（配额数学不成立，多用户场景必死）；② 自搓 WS 客户端（握手协议私有，spike 确认走 `msg-frontier` 私有服务）；③ `receive_mode` 开关（降级已是自动行为，开关只增加误配面）；④ 纯事件不留 Sweep（断线窗口消息永久丢失，丢的是游标续拉这一差异化承诺）；⑤ Jira webhook 触发即时镜像（留作 future work，本期镜像延迟由 forward 快循环保障）。
