# 0028 — 生成物按段裁剪：模板保持 canonical、生成侧向下注释

`tasking init` 生成的 `WORKFLOW.md` 曾整份照搬模板：可选段全以默认值平铺、`router`（无运行时代码的死配置）与 webhook 预留字段也活着，新手面对 200+ 行「没配的」。本变更让生成物只把必需段保持 active（`tracker`、Jira 变体的 `hooks`/`env`、启用时的 `feishu`），其余可选段整段注释、段首一句「可选：以下为默认值，改动才解注释」；死配置（`router`、feishu `verification_token`/`encrypt_key`）在模板与生成物中注释并标注未实现/预留；非交互 init 也改走同一生成路径（不再逐字节复制）。注释采用「在原模板 active 行上加 `# ` 前缀」，注释文本永远来自模板这**单一真相**。

被否决：**模板全注释 + 生成时解注释**（sshd 式）——要从注释文本重建 YAML 结构，正则失配是静默丢字段，且模板 parse 出来为空会摧毁漂移检测/语言对齐/DEFAULTS 覆盖三处以模板为基准的机器（其中漂移检测的基准后于 ADR 0034 改为生成器当日产物）；**从代码骨架序列化 frontmatter**——模板与骨架两份真相互相漂移；**为 router 补运行时实现**——不作为本变更范围，留作预留配置。
