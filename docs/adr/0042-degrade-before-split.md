# 降级优先于分段：旧面板先失去输出，永不丢面板

ADR 0041 让轮次卡片「溢出优先分段、每个面板保留完整 15 行输出」，长轮次因此每张卡只能放 10–20 个工具，用户要翻几张卡才能看清 agent 做了什么。本 ADR 记录反转：**卡片超预算时先按最旧优先把工具面板的输出 15 行 → 3 行 → 去掉（始终保留 Args/Command），全部降到无输出仍装不下，才把最新尾部切到新卡片；永不丢面板，最新尾部保持完整。**

被否决的方案：维持「优先分段」（单卡工具少、卡片多）；逐面板降到底（老工具完全无输出，最新几个才完整）；单卡窗口模式（隐藏旧事件、丢失历史，且需要新配置）；保留 level 3 丢弃面板（与「永不丢面板」冲突）。

**Consequences.** 历史卡是「密集索引」：一张卡能重新放下 40–50 个工具，输入都在，旧输出不在卡上；最新卡保留完整明细（15 行 Output）。`📄 完整输出` 与 TUI 仍是旧输出的获取路径；单个面板的 Command/Args 在 level 2 下限制在约 2KB 并可按需继续截断。多段轮次正文第一行显示 `本段 X · 本轮 Y`；「还有 N 个工具调用未展示」与 level 3 被移除。无新增配置/数据库/开关；回退方式是 revert 或把 `feishu.direct.verbosity` 设为 `summary`。ADR 0041 的「优先分段」表述由本 ADR 修正，其余结构（事件流、分段、封存、活跃段按钮、1MB 明细）保持不变。
