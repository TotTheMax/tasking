# Same-directory turn concurrency is opt-in, not an invariant

ADR 0022 made per-directory turn serialization mandatory to protect shared working trees. We keep that as the **default** but make it an explicit opt-out: `feishu.direct.max_concurrent_turns_per_dir` (default `1`) bounds how many direct-session turns may occupy one fixed directory at once. Raising it is a deliberate, user-owned trade-off — concurrent agents share the same files and git index, so tasking does not attempt to make such runs safe. The global `feishu.direct.max_concurrent` still caps concurrency, and the effective per-directory limit is the stricter of the two. We rejected deleting the directory lock (unsafe for every deployment), a boolean bypass (no predictable bound), per-project overrides (ambiguous when project names alias one real path), and automatic read-only detection (an agent can still edit or run shell commands). Operator visibility comes from a startup/reload WARN, a per-turn log field, and the `direct_dirs` array in `/api/v1/state`; TUI and `tasking doctor` are unchanged.

**Status**: accepted; amends ADR 0022's "per-directory serialization is mandatory" to "the default, with an explicit config opt-out".

**Considered Options**: remove the directory lock entirely (rejected: silently unsafe for all users); boolean `allow_same_dir_parallel` (rejected: unbounded within the global cap); per-project limit (rejected: same real path can be reached through several project names); read-only concurrency with ruleset enforcement (deferred: needs a read-write lock and a verified read-only posture, a separate decision).
