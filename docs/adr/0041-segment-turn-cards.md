# 轮次卡片按事件源顺序渲染，溢出优先分段

直连轮次卡片曾把一轮过程拆成 `texts` 与 `tools` 两个数组、渲染时先铺完文本再铺工具，并在单卡接近 24KB 预算时只对工具做三级降级。这既丢掉了「思考 → 执行 → 再思考」的阅读顺序，也让长轮次里的工具明细被文本挤出卡片——而工具明细正是解释 agent 在做什么的关键信息。本 ADR 记录替换：**过程面是一条有序事件流（Turn event：一段 assistant 文本或一次工具调用），按源顺序渲染；超出预算时优先把尾部事件放进新的分段卡片（Segment card），降级只作为「单条事件自身装不下」的兜底。** 需求见 OpenSpec `segment-turn-cards`；本文只记录决策与取舍。

被否决的方案：保留两个数组、给每段维护两个起始下标（改动更小，但顺序依旧分组，且游标数量翻倍）；先测量再添加（需要把渲染拆成 measure + render，并对每条事件重复测量）；每次 flush 重新贪心装箱（会改变历史分段，已发卡片需重排）；段数上限 + 到顶改文本投递（多一套策略与计数器，且用户明确要求不设上限）。预算计量改为实际发送 envelope 的 UTF-8 字节（`translate` 出口翻译 + JSON 转义），因为原实现的字符数会显著低估中文与转义后的体积；同时以近似元素数（固定开销 + 文本 1 + 工具面板 3）兜住飞书单卡 200 元素的上限。

**Consequences.** 一个长轮次可能产生多张分段卡片（不设上限），旧段在切段时密封为「— 本段结束，续见下一条卡片 —」，只有活跃段保留控制按钮；`📄 完整输出` 语义不变，仍只导出整轮工具明细。单卡超过 5 个表格、以及「建段成功但写库前崩溃」留下的孤儿按钮卡，作为已知限制记入 `known-issues`。回退成本低：revert 代码，或把 `feishu.direct.verbosity` 设为 `summary` 立即退回文本交付。ADR 0024 中「within-turn 预算降级」的表述由本 ADR 取代。
