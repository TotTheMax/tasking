# 0032 — direct verbosity 默认 detailed：卡片开箱即用

ADR 0024 把轮次卡片做成 opt-in（默认 `summary`），唯一理由是折叠面板的客户端下限：飞书/Lark 客户端低于 V7.9 会把面板渲染成「请升级」占位符，且服务端无法探测查看者的客户端版本。本 ADR 记录默认值翻转为 `detailed` 的决策：**「老客户端看到占位符」从阻止默认放开的理由，降级为一条文档写明的版本要求**。依据是实际运行中卡片体验（逐工具折叠面板、失败展开、中断/重试/完整输出/结束按钮、markdown 结果卡）显著优于一行统计，且团队内客户端版本可控；用户决策 2026-10-09。

被否决的替代：**服务端探测客户端版本按人降级**——卡片 API 不暴露查看者版本，卡片 JSON 一次性分发无法按接收者定制；**检测占位符反馈提示改 summary**——占位符是客户端本地渲染，没有信号回路；**新增第四档 `auto`**——无探测依据则 auto 与 detailed 无差异，多一档配置面、校验与双语文档，纯成本。接受的后果与缓解：默认部署下 < V7.9 客户端看到升级占位符（飞书官方提示、非报错；结果投递不受影响），版本要求写入模板注释与 `docs/{zh,en}` 双语文档，`verbosity: summary` 一行显式回退；默认路径调用量从「每 turn 1 条文本」升为「1 卡创建 + 周期 PATCH（1.5s 合并）+ 1 结果卡」，ADR 0024 的合并/预算硬上限保留。

连带语义变化：detailed 的一次性控制台配置（`im:resource` scope、`card.action.trigger` 长连接订阅，生产与 E2E 两 bot 各一份）从「启用 detailed 的前置」升级为「启用直连的前置」；未配置时仍按 ADR 0024 降级为合并文本消息（WARN），不阻断。既有部署中显式写了 `verbosity: summary` 的不受影响，未写 verbosity 的升级后交付形状变化即为本次变更目的，release note 需提及。
