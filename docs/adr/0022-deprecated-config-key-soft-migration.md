# 改名配置键忽略旧键 + 弃用警告，而非硬报错

ADR 0018 将 `feishu.poll_interval_ms` 改名为 `forward_interval_ms` 时决定「旧键硬删不做别名、validator 报错即迁移指引」——实际后果是用户升级二进制后未同步改 WORKFLOW.md，`tasking start` 启动即崩（旧键即使 `feishu.enabled: false` 也致命，且热重载永久拒绝新配置）。决定反转：resolver 对改名键**不映射、不报错**——旧键存在时忽略其值，新键 `forward_interval_ms` 缺省取默认 5000（可用性由默认值保障），同时发出 WARN（含改名原因与迁移指引），daemon 正常启动；警告经 `ConfigManager.warnings` / `ConfigReloadResult.warnings` 透出，由 daemon 启动与 reload 时写日志。

理由：新键已有默认值，可用性天然成立，旧键无需参与解析——映射反而让旧键值（旧语义为收发合并节奏）悄悄注入新语义（仅 Jira→飞书镜像节奏），语义并不等价。被否：① 维持硬报错（用户体验：升级即坏）；② 旧键值映射到新键（语义不等价 + 别名掩盖误配，用户永远不迁移）；③ 静默忽略不警告（用户无从得知需迁移）。代价：用户旧键里的自定义值不生效，需迁移到新键才恢复（警告已指引）。此决策确立通用策略：**配置键改名后旧键一律「忽略 + 弃用警告」，新键必须有默认值兜底，禁止启动期因旧键直接失败**。回滚即 git revert；无存储迁移。
