# Pause anchors the TUI viewport to a stable entry, not an offset

The TUI Log/Activity views let the user pause live-follow with `Space`/`f`, showing a `[paused]` tag. The view kept scrolling anyway because a paused viewport was expressed as either `null` (renderer fell back to "follow the tail") or a numeric index into the renderer's sliding `recent(200)` window, which drifts forward every time the tail window slides once the buffer holds more than 200 lines. Paused views therefore anchor on the identity of the topmost visible entry and render from wherever that entry currently is; if it has rolled out of the available window, the view stays put at the oldest still-available entry rather than jumping to the tail. Resuming follow clears the anchor and returns to the newest lines. Absolute content identity is the only anchor that keeps a paused screen still under a growing log buffer — offsets and window indices both drift (see the partial `cd6842e` fix, which only held below 200 buffered lines).
